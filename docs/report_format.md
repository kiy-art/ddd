# 社長室への報告ルール（PAR. 経営ボード）

社長が決めた報告の書き方（2026-10-06）。Claude Code の報告（チャット・Notionの「報告（Code → 社長室）」）と、社長室（Claudeプロジェクト）の回答の両方に使う。

報告は「社長が判断・作業すること」と「報告だけ」を必ず分ける。混ぜない。

## 冒頭（3行）
1. 社長がやることは何件か（判断A何件、作業B何件。0件なら「今回は何もしなくて大丈夫です」）
2. いちばん近い期限（なければ「なし」）
3. 今週のいちばん大事な結果（1行）

費用が発生すること、無料トライアルや申請の期限など、後から困る制約は、冒頭に書く。

## 本文（この順番・この見出しで固定）
- **🔴 A. 社長の判断が必要なこと**：承認依頼・選択のみ。1件ごとに「何を決めるか」「選択肢とおすすめ」「期限」「決めないとどうなるか」。なければ「なし」。
- **🟡 B. 社長にお願いしたいこと（作業・確認）**：判断ではなく手を動かすこと。1件ごとに「何のため」「自動化の度合い」「手順」「期限」「終わったら何をするか」。なければ「なし」。
- **🟢 C. 報告のみ（対応不要）**：実行したこと・結果・数字。結論を先に1行、詳細は短く。
- **⚪ D. 参考（読まなくてよい）**：技術的な詳細・経緯。トグルに畳む（チャットでは最後に短く）。

## Bの書き方（初心者でもできるように）
- 手順は番号つきで、1手順に1動作。画面の名前・押す場所を具体的に書く。
- Chrome上のClaude（Claude in Chrome）でできる作業は、できるだけ自動化し、社長がそのまま貼れる依頼文をコードブロックで付ける。
- 社長がやるのは、ログイン、規約への同意、送信、電話、申請の最後のボタンなど、本人しかできない部分だけにする。
- 自動でできないときの手動の手順も書く。
- 結果は社長室のチャットに貼ってもらい、受信箱に書いてもらう流れにする。
- 依頼文には、秘密情報（パスワード・APIキー）を貼らせない・読み上げさせないことを必ず書く。

## その他
- AにCや技術的な説明を混ぜない。逆も同じ。
- Notionの「要対応」は、AまたはBがあるときだけオンにする。
- 専門用語・略称は、使うなら一言で意味を添える。
- 受信箱で社長室が決めたことには、対応した結果を必ず返す（受信箱の「対応メモ（Code）」と、報告のC）。
- 見本：Notionの報告「#003・#004の実施報告と、楽天キーワードの修正の続き（2026-10-06）」
