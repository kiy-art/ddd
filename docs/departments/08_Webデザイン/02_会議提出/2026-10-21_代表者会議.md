## 議題0：各部署の目標の進み具合(遅れている部署と理由)
- 推す案：Webデザインの遅れは「計測不足」型と分類する。次の1週間の優先は ①管理APIにPVの7日合計（または日別）を足す依頼をSEへ → ②日次スナップショットの積み上げで10/31に基準値を出す → ③画面の変更は1回に1か所。
- 理由：
  - 基準値が出ない原因は、GA4が1日窓のみ（10/20のPV 8、`window_days=1`）で、クリックは7日・30日の窓だから（kpi/2026-10-22.json、knowledge.md 2026-10-16・10-21）。作業の遅れではなく、データの形の問題。
  - ショップクリックは累計25・直近7日0・前7日7（kpi/2026-10-22.json）。10/19にトップ刷新第1段階を公開した後の7日で`last_7d_by_placement`が空＝`home_top_pick`も0件。ただし母数が小さく（PVは1日8）、刷新が原因か、全体の流入減かは判定できない（推測）。「効かなかった」とも「効いた」とも言わない。
  - 10/31が基準値の日（PVが取れ始めた10/17から14日、knowledge.md 2026-10-18。推測）。トップ刷新の前後2週間の判定は、公開日10/19の2週間後＝11/2以降。
- 見込み効果：控えめ（計測が整うだけで、クリックは直接増えない）。月60クリックの目標との距離は、画面だけでは埋まらない（推測。流入が先）。
- 費用・リスク：費用0円。リスクは、PVの項目追加がSEの作業になり、他の優先（Yahoo API 429など）に押されること。
- 決裁レベル：A
- 過去の試行：EXP-001（購入ボックス上移動・固定バー、2026-09-30）は結果「未測定」で、マラソン（10/4〜10/9）とデプロイが重なり交絡あり。EXP-004・EXP-010も実施前が未取得または未測定（experiments.csv）。「効いた」と言える画面施策はまだ無い。
- 市場・時期：10/24付近に楽天マラソン第3弾の予想（議題1。公式は未確認）。前後比較にセールが重なる期間は別に注記する（market.md「実験の解釈」、スキル追加点検）。
- 測り方：毎晩の`kpi/*.json`のPV（日別）とクリックの差分を積む。10/31に「合計クリック÷合計PV」を基準値とし、欠けた日は「欠測」と書く。

## 議題2：公式情報の確認と社長作業の一本化
- 推す案：
  - 社長に頼む確認を1枚にまとめる形に賛成。Webデザインから社長への依頼は無し（画面はコードと本番HTMLで確認できる）。
  - EXP-008（reorder_homepage）の自動実行は、**止める案に賛成**（レベルA）。再開は、トップ刷新の前後比較（11/2以降）が終わってから。
  - Yahoo更新が1日14件前後の件は、「画面に価格が出る順」で優先する案（下記）。
- 理由：
  - EXP-008：判定済み23件のうち悪化22・改善1、未判定5（auto_pdca_ledger.csv 2026-10-22、kpi/2026-10-22.json）。ただしexperiments.csvは「件数が少ない・判定不能」とも書いており、判定の方法（何と比べて「悪化」か）は私は未確認。その確認はSEへの宿題。
  - 画面側の理由が一番大きい：この自動施策はトップの並びを入れ替えるため、私が測りたいトップ刷新の前後比較（`home_top_pick`）の条件を毎日変えてしまう（交絡。推測）。止めない限り、基準値の10/31と前後比較の11/2が濁る。
  - Yahoo更新：全676件を約48日で一巡（議題の推測）。価格が7日超古いと画面に数字が出ない（`OFFER_MAX_SHOWN_DAYS`、knowledge.md 2026-10-11）。公開中の429件のうち、ランキング・トップ・クリックが多い商品から先に更新すれば、購入導線の弱さを減らせる（意見。実装はSE）。
  - 公式情報が確認できない件：画面では「料率」「施行日」を書いていないので、直接の影響は小さい。当部のスキル一次情報（WCAG 2.2など）も今夜は未確認で、knowledge.mdに確認日はまだ無い。
- 見込み効果：EXP-008停止＝控えめ（測定の信頼性が上がる効果。クリックの増加は見込まない）。Yahoo優先順＝標準未満（推測。Yahoo経由は店別累計3件のみ、kpi/2026-10-22.json）。
- 費用・リスク：停止の費用0円。リスクは、自動の並び替えが仮に改善に効いていた場合の機会損失。ただし改善は23件中1件で小さい。停止はいつでも再開できる。
- 決裁レベル：EXP-008停止＝A、社長作業の依頼＝C（議題の見込みのとおり）。
- 過去の試行：EXP-008（STEP42から。experiments.csv）＝30日で判定不能、継続（自動）。10/05時点は悪化2・改善1・未判定12、10/22時点は悪化22・改善1・未判定5（auto_pdca_ledger.csv）。悪化が増えた原因（判定が進んだだけか）は未確認。
- 市場・時期：なぜ今か＝10/31の基準値と11/2の前後比較の前に、トップの条件を安定させるため。market_ledgerではカテゴリの30日変化の中央値はほぼ0.0%（2026-10-22行）で、市場の大きな動きに合わせた並び替えの根拠は薄い（推測）。
- 測り方：停止日をexperiments.csvに記録。停止後のトップ起点クリックを、`home_top_pick`＋トップ分`product_card`の合計で見る。
