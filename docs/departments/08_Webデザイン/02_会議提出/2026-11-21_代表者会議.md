- 費用・リスク：費用0円。リスク=達成済みの目標を理由に画面改善を続けると、集客の遅れを見えにくくする。
- 決裁レベル：A
- 過去の試行：UI系 EXP-027(/popular楽天枠の文言、判定11/25、未測定)。判定できたUI施策は0件(11/18意見書)。
- 市場・時期：BF(楽天11/19〜11/25、Yahoo!11/22〜、Amazon11/27〜)は通常期と別枠で記録。

## 議題2：セールガイドからショップへ進まない件(P-011)と、BF後(11/26〜)のガイド
- 推す案：①P-011は「新しい計測は足さず、既に記録される guide_card・guide_end(累計0)の結果で判定」(コード上は実装済み、本番で特集6枚・末尾ブロックの表示を確認)。SEが今夜何を足すかは、変える場所(page.tsx・GuideEndShops)が重なるので記録で明記。②画面は「並び替えpatch」を11/26に単独適用 → 12/3に11/20の根拠文patch、の順に日を分ける(patch:`01_部内検討/2026-11-21_ガイド特集の並びを確かな値下がり優先に.patch`、git apply --check合格)。③BF後のガイドは同じURLの改題(型落ち・ギフトは別URLの新ガイドより、既に検索クリックがあるこのURLを使う案。推測)。Yahoo!節の追加は、日程の公式確認(LYコーポ11/2リリース)が取れた範囲だけ。「上限7,000円相当」は載せない。
- 理由：今夜わかった点=本番の特集6枚の根拠文が全て「記録上の差。販売店・条件の違いの可能性あり」(25%以上は%を出さない仕様+大きい順に並ぶため。lib/deals.ts、本番HTML)。一方 /deals には%が出る25%未満の値下がりが14件ある。押す理由が無い表示になっていた(推測)。主因はPV約1/日(P-011)で、画面では直せない。
- 見込み効果：控えめ=+0クリック/月(判定不能のまま)、標準=+1〜2/月(PV30/日に増え率5%が成立した場合の算数。PVが増える根拠は無い)、強気=根拠なし。EPC仮値6円なら月+数円〜十数円で、利益1万円には届かない。意義はクリック率の基準を作る土台。
- 費用・リスク：費用0円。デメリット:①判定不能の公算大(1群約450PV要)、②最大60%の値下がりが外れ、関心が大きい差にある場合は逆効果(推測)、③値下がり率の根拠(記録の日付)が出ない問題は残る、④商品が日替わりで入れ替わり前後比較が混ざる、⑤SEのP-011と同じファイル(page.tsx)を触るため日を分ける必要、⑥監査(景表法)が要る。
- 決裁レベル：A
- 過去の試行：EXP-019・021・022・026・028・029(ガイドの本文・title・日程、すべて「未測定」)、EXP-027(11/20、/popular文言、未測定)。ガイドのクリック増を示した施策は0件。ガイドの「ボタンの見せ方」を試した行は無し。
- 市場・時期：BF後(11/26〜)は年末ギフト・型落ち需要(推測、検索量は未取得。事実.md)。楽天BFは11/25 1:59終了で、11/26から単独でUI変更を入れやすい。ただしYahoo!(11/29まで)・Amazon(11/27〜12/7)は続く。
