## 議題1：事業の見通しと、2027年3月末までの方針

### 先に答える：今の主な問題は「クリック率」ではなく「人が来ないこと」

数字で判断する。

| 項目 | 値 | 出典 |
|---|---|---|
| 1日のPV（GA4） | 8〜12（10/17:8、10/18:8、10/19:12、10/20:8、10/22:9。10/21は欠測） | `kpi_ledger.csv` |
| 直近7日のショップクリック | 2（前7日7） | `kpi/2026-10-23.json` |
| PVあたりクリック率（暫定） | 約3.5%（2クリック÷57PV。PVは6日分のみで過小＝上限寄り。判定不能。10/31に確定予定） | `knowledge.md` 2026-10-22 |
| 3月末に必要なクリック | 月2,400 | 議題1（ボードの goals） |

計算（私の計算。前提はクリック率3.5%＝上の暫定値）：
- 月2,400クリックに要るPV＝2,400÷0.035＝約68,600PV/月（1日約2,300PV）。今の1日8〜12PVの約200倍（推測：前提は暫定値）。
- 画面でクリック率を2倍の7%にできたと仮定しても、要るPVは約34,300PV/月（1日約1,100）で、今の約100倍。クリック率をどれだけ上げても、PVの桁が足りない。
- 逆に、今のPV（月約300）なら、クリック率が3.5%でも月約10クリック。目標の月60にも、画面だけでは届かない（推測）。
- 画面の改善が「測れる」かも別の問題。3.5%を4.2%（約2割増）に上げた差を見分けるには、1案あたり約11,000PV要る（概算：n≒16×p(1−p)÷差²、p=0.035、差=0.007。統計の一般式による私の計算で、推測）。今のPVでは約3年かかる。つまりクリック率の小さな改善は、今は判定不能になる。

結論：主な問題は集客（PVが桁違いに少ない）。クリック率は、入口（来た人の行動）としては暫定3.5%で、極端に低いとは言えない（比べる基準は未取得。他サイトの平均値は出典を確認できていないので書かない）。

### 決めたいこと2：3月末までに何に集中するか
- 推す案：**集中は「検索から来る入口の数を増やす」1本**。画面（Webデザイン）の仕事は、その入口の「受け皿の型を整えること」に絞る。クリック率の細かい改善は、PVが1日100前後になるまで止める。
- 理由：
  - 上の計算のとおり、集客の桁不足が主因。
  - すでにコードには、商品ページ・カテゴリ×メーカー（`app/category/[category]/[brand]`）・2商品比較（`app/compare/[pair]`）・ガイド（`app/guides/[slug]`）などの入口の型がある（`frontend/app/` のファイル一覧）。型があるなら、増やす作業は主にデータとコンテンツ側（SE・マーケ）。
  - 検索表示の直近の落ち込み（集計ページ数22→10。原因は未確認）は、画面の問題かどうか不明。まず原因を確認するのがSEの仕事。
- Webデザインが引き受けること（具体案）：
  1. 検索から来る入口ページ（カテゴリ×メーカー、比較）に、`StoreComparisonTable` と `StickyBuyBar` を同じ型で入れる。商品ページと同じ導線（価格→店→ボタン）が検索の入口でも使えるようにする（レベルA。コード変更は監査後）。
  2. 表示速度と表示のずれ（CLS）の点検。検索の入口は速度で順位に影響しうる（Core Web Vitals。一次情報は今夜未確認）。
  3. 375px幅の確認用モックを先に作る（スキル追加点検。`next build` がAPIなしで失敗する問題の回避。knowledge.md 2026-10-17）。
- やらないこと：色・余白・ボタン文言の細かいA/Bの追加。PVが少なく判定不能になるため（上の概算）。
- 他の選択肢への意見（画面の観点だけ）：
  - 報酬の高い案件を足す：ボタンの置き場所は用意しやすい（`partner_clicks` の枠があり、累計0件）。ただし今のPVでは、単価が高くても件数が出ない（推測）。案件の中身・条件の評価は営業・経理の領域で、意見なし。
  - X・SNS：10/21に商品写真つきカードを作成済み。効果は未測定（EXP-007が「未測定」）。UTM計測の結果を見てから判断。
  - 費用を下げる：画面側にはほぼ手が無い。
  - 別の事業へ移る：デザイン視点では判断材料が無い。意見なし。
- 見込み効果：控えめ。入口ページの型の統一そのものでクリックは直接増えない（流入が先。推測）。
- デメリット・できなくなること・リスク：
  - 画面の改善を止めると、トップ刷新（10/19）や購入ボックス改善の効果検証が長引く。「効く画面」の知見が溜まらない。
  - 入口の型を増やしても、検索で拾われるかはSEOの領域で、画面では保証できない。
  - 集客1本に絞ると、ほかの収益の芽（案件の拡張・別事業）を試す時間が減る。
  - 375px確認用モックの作成に、作業時間がかかる（費用0円）。
  - 画面が主因ではないという私の判断は、クリック率の基準値が暫定（3.5%、判定不能）であることに依存する。10/31の確定値が1%を割るようなら、見方を戻す。
- 決裁レベル：A（コード変更の個々の施策）。方針全体の位置づけはB。
- 過去の試行：EXP-003（カテゴリ×メーカー・比較ページ追加、2026-10-03）の結果は「未測定」。入口を増やす施策がどれだけ検索表示を増やしたかは未取得（`experiments.csv`）。
- 市場・時期：秋の需要期（〜11月）と、型落ち値下がりの年末年始（`market.md` 2026-10-05、一般論の記事。個別商品の見込みには使わない）の前に、入口の受け皿を整える意味がある。楽天スーパーSALE 12月（予想：12/4〜11、公式未確認）の前に、ランディングの型を整えておく。

### 決めたいこと3：方向を変える数字と日付（撤退・見直しの線）
- 推す案：**「集客の線」を主に置き、「クリック率の線」を補助にする**。デザインの立場から出せる線を示す。全体の線は経営企画・経理の案も合わせて決めてほしい。
- 線（日付と条件。数字は議題の段階目標と、上の計算を基にした私の案）：

| 日付 | 見る数字 | 続行 | 見直し（方向を変える議論を開く） |
|---|---|---|---|
| 10/31 | クリック率の基準値（PV14日以上） | 2%以上 | 2%未満なら、画面の問題の疑いを上げる（集客より先に画面を直す） |
| 12/7（経営企画の既存の線） | 柱のページの検索表示（月） | 500回以上 | 500回未満（議題1の事実） |
| 12月末 | ショップクリック（月） | 400（段階目標）の半分の200以上 | 100未満なら、集客策の抜本的な見直し（議題2の集中先を変える） |
| 2027-01-11（経営企画の既存の線） | 柱経由のショップクリック（月） | 30以上 | 30未満（議題1の事実） |
| 3月上旬 | 月のクリックと1日のPV | 月1,000以上かつ1日PV約1,000 | それ以下なら、3月末の月1万円は届かないと確定し、継続か撤退かを社長が決める |

- 「方向を変える」より先に確認すること：12月末にクリックが100未満でも、PVが伸びていてクリック率が落ちているなら、画面側（私の部署）の問題。PVが伸びずクリック率が正常なら、集客側の問題。この見分け方を線に添える。
- 理由：クリック率だけの線だと、PVが少ない今は数字が動かず判断できない（判定不能になる）。PVと検索表示の線を主にしないと、線が意味を持たない。
- 見込み効果：判断の遅れを防ぐ。線を決めないまま続けると、費用だけが積み上がる（月約5,500円×残り月数）。
- デメリット・できなくなること・リスク：
  - 線は私の暫定のクリック率（3.5%）とPV（過小の可能性）に依存している。10/31の確定値で引き直す必要がある。
  - 線を厳しくしすぎると、季節要因（11月までの需要期と、冬の閑散。推測）で早まって撤退する恐れがある。逆に甘くすると、判断が遅れる。
  - 日付は10/21の議事録・議題の既存の線に合わせたため、他部署の案と食い違う可能性がある（私は他部署の意見書を今夜読んでいない）。
  - 楽天のレポートのクリック数（7日で79）はボット・社内AIの混入の疑いがあり（議題1・推測）、線の数字には使わない。サイトの記録のみを使う。
- 決裁レベル：B（社長の判断）
- 過去の試行：撤退・見直しの線そのものを置いた試行は無し。経営企画の12/7・2027-01-11の線が既にある（議題1の出典）。EXP-008（自動入れ替え）は、悪化の定義が曖昧なまま判定が進み、10/22に停止になった。判定の定義を先に決めないと、線が機能しないという前例（`experiments.csv`）。
- 市場・時期：楽天スーパーSALE（12月・予想）は線の12/7〜12月末の期間と重なる。前後比較にはセール期間の注記を付ける（`market.md` 実験の解釈）。Amazonアソシエイトの期限は2027-03-21ごろ（議題1の推測）で、3月上旬の線と近い。
- 測り方：毎晩の `kpi/*.json`（クリック、PV、検索表示）を積み上げ、線の日付に表で報告。欠測日は「欠測」と書く。

## 少数意見・懸念（部署の中で割れた点があれば）
- 部内の割れは無し（担当は1名）。
- 最大の懸念：クリック率3.5%は、分母のPVが6日分で、GA4が1日窓のため過小な可能性が高い（`knowledge.md` 2026-10-22）。この数字で「問題は集客」と断定するのは強い言い方になる。ただし、クリック率が仮に3.5%の半分でも、あるいは倍でも、必要なPVとの差（約100〜400倍）は逆転しない（私の計算）。結論の方向は、数字が多少ずれても変わらない。

- 私は自分の暫定値に引きずられる危険がある。画面を改善するほど「改善した」と言いたくなるが、効果は一度も測れていない（experiments.csv）。
