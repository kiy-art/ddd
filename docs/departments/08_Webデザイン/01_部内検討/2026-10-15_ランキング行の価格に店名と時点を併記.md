# 2026-10-15 ランキング行の価格に店名と時点を併記（/popular）

## 1. 基準値（クリック率）
- 取れた数字（出典: 管理API 2026-10-15T15:08Z、Search Console 3日）
  - GA4 PV: 25（10/14の1日分・11ページ）
  - ショップクリック: 30日25件、直近7日7件
  - 場所別累計: 人気ランキング(楽天)8、商品CTA7、店舗比較5、CTA_alt3、商品カード1、消耗品1（合計25。ランキングが最多で32%）
  - Search Console（3日）: 表示28、クリック4
- クリック率（クリック÷PV）: **未取得**。PVは1日分、クリックは7日・30日で期間が合わない。「7÷25＝28%」は期間違いなので使わない。
- 取り方の提案: GA4で「直近7日のPV」と、同じ7日の `cta_click`（placement別）を同じ画面で取り、/popular のPV当たりの `popular_rakuten_ranking` クリックを基準にする。管理APIにPVの7日合計が無ければSE（システム担当）に追加を依頼。
- 反映日とクリック件数の記録は、パッチ反映日に experiments.csv へ「変更前7日の値」を先に書いてから行う。

## 2. 問題と仮説（1文）
ランキング行の価格（`¥xx,xxx`）には店名も時点も付かず、「いつ・どこの価格か」がわからないので、押す前に迷う。楽天のランキング取得時点の価格だと明示すれば、迷いが減りクリックが上がる（効果の大きさは推測。PVが少なく判定不能もありうる）。

場所別で最多の `popular_rakuten_ranking`（8件）を伸ばす意味は大きい。変えるのはこの1か所だけ。

## 3. 現状のコード確認（読むだけ）
- `frontend/app/popular/page.tsx` 112〜139行: 価格は `yen(entry.price)` のみ。時点は上部の説明文（取得日時）にあるだけで、行から遠い。
- 同 96行: 店名・レビューは `text-foreground/45`（11px）。スキル4章とknowledgeの計算では /55＝約3.8:1で、/45はさらに低くAA未達。
- 同 133行: 「価格推移・他店比較を見る →」は11px・/50・高さが小さく、タップしにくい（目安44px未満）。他店比較（比較表）へ流す大事な導線。
- PR表記は200行（PR）と238〜240行にあり、今回触らない。

## 4. 提案（パッチ）
変更点3つ（すべて RankingRow 内、同じ1か所の改善）
1. 価格の下に「楽天市場・M/D HH:mm時点」（`fetchedLabel(active.fetched_at)`）を表示。文字は /65 以上。
2. 店名・レビュー行を /45 → /65（AA）。
3. 「価格推移・他店比較を見る」を /50 → /65、`py-2`付きで高さを広げる。

景表法: 「最安」は使わない。「楽天市場の価格」と時点だけを書く（比較・最安の主張なし）。PR表記は変更しない。
