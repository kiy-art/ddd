## 2. 現状(コードを読んだ事実)
出典: frontend/lib/shopOffers.ts、frontend/lib/shopRows.ts、frontend/components/StoreComparisonTable.tsx、frontend/app/products/[slug]/page.tsx(395〜545行)。
- 店別価格とボタンは商品ページに既にある。購入ボックスの主ボタン(product_detail_cta)=取得3日以内の価格で最安の店、他店ボタン(product_detail_cta_alt)=価格・差額(+¥)・時点つき、比較表(store_comparison)=並び順は「新しい価格を安い順→古い価格→価格なしの検索リンク」。
- 古い価格の扱い:取得3日超は「最安」の比較に入れない(OFFER_FRESH_DAYS=3)。7日超は数字を出さず「価格は販売ページで確認」(OFFER_MAX_SHOWN_DAYS=7)。3〜7日の価格は行に残り「N日前の価格」が付く。比較表は「N日前の価格(◯/◯ 時刻 時点)・最新は販売ページで確認」と出る。時点は時刻まで表示(formatUpdatedAt)。
- 穴1:購入ボックスの他店ボタンで、3〜7日前の古い価格が新しい価格と同じ大きさ(text-base)の数字で出て、日数は左の小さい補足(truncate=スマホで切れうる)にしか無い。BF中は価格が日々動くので、数字だけ見て「今の価格」と読まれうる。
- 穴2:価格カードの「他店 ¥◯◯」が text-foreground/40、購入ボックス見出しが /45、最安の補足が /55。白地のコントラストは /55≈3.8:1、/45・/40はそれ以下でAA(4.5:1)未達(knowledge.md 10/11 の計算)。時点つきの注記が読めないのは、時点表示を薄くしないというスキル5章に反する。
- Yahoo!の更新が少ない事実:11/14は更新14件/スキップ785(API 429)=Yahoo!価格の多くは3日超で「最安」比較から外れる(出典:事実.md 11/14)。

## 3. 変更(patch。1文の仮説つき)
仮説:「古い価格が新しい価格と同じ大きさで出る・時点の文字が薄いので、価格の鮮度が読み取れず他店ボタンを押す判断が弱い。古い価格を小さく・日数を数字の真下に置き、時点の文字を/65にすれば、誤認が減り比較が読まれる」(クリック率への効果は未検証の推測)。
1. 他店ボタンの古い価格:text-base→text-sm、数字の真下に「N日前の価格」(日付不明は「取得日時不明」)。
2. 価格カードの「他店 ¥◯◯」/40→/65、最安の補足/55→/65。
3. 購入ボックス見出し/45→/65。
変えないもの:PR表記、時点表示の内容、主ボタンの選び方(3日以内の最安)、並び順、placement名(測定の連続性)。

## 4. デメリット・リスク(メリットと同じ重さで)
- 効果は測れない:PV約4〜10/日では、1か所の変更の前後比較は判定不能(11/10記録:2倍検出に約454PV/群)。目的は誤認防止と可読性(守り)で、クリック増は期待しているが根拠なし。
- 他店の新しい価格が濃くなる=最安店以外の価格が目立つ。主ボタンへの視線が少し分散する可能性(推測)。
- 基準期間(11/4〜11/17)の途中で表示を変えると基準値が汚れうる。→適用は11/18以降(基準値確定後)が望ましい。BF(11/19 20時〜)前に適用するなら11/18夜〜11/19。
- 古い価格を小さくしても、3〜7日前の価格が見え続ける。BF中は「見せない」(閾値を3日→1〜2日に短縮)案もあるが、Yahoo!の更新が1日14件程度のため比較に入る店が減り、「店別比較」自体が成立しなくなる。短縮は、新しい価格の商品数(未取得)を数えてから判断。今夜は出さない。
