## 2. 仮説（1文）
他店ボタンが「店名の一覧」に見え、価格と時点も読みにくいので押されない。各ボタンを「◯◯で見る／◯◯で探す」＋2行目に価格の時点＋右に価格（2番目以降は差額）＋矢印の1列に変えれば、`product_detail_cta_alt` のPVあたりクリックが上がる（上がり幅は**推測**。過去データが無く数値は置かない）。

ユーザーが迷う点のうち「どこで（どの店へ行くボタンか）」と「いくらで（その価格はいつのものか）」に当たる。

## 3. 変更内容（1ファイル、購入ボックスの他店ボタンだけ）
- 変更ファイル：`frontend/app/products/[slug]/page.tsx`（他は変えない。主ボタン・固定購入バー・比較表は今回は触らない＝1回に1か所）
- 他店ボタンの並びを常に1列に（2列だと「Yahoo!ショッピングで見る」＋価格が狭くて切れる）。
- 1行目：`shopButtonLabel()` … 価格のある店・商品ページ→「◯◯で見る」、検索結果へのリンク→「◯◯で探す」。

- 右端：価格がある店だけ価格。2店以上の新しい価格を比べられたときだけ、2番目以降に差額「+¥1,200」。古い価格は差額を出さない（比較の根拠にしない）。
- 末尾に矢印（`CtaArrow`、主ボタンと同じ部品）。高さ 48px 以上、角丸は `rounded-2xl`（2行になるため）。
- 計測の名前（placement）は `product_detail_cta_alt` のまま＝前後で比べられる。

## 4. ボタン文言（ux-copy の観点）
| 場面 | 文言 | 理由 |
|---|---|---|
| 価格のある店・商品ページへ | 「楽天市場で見る」「Yahoo!ショッピングで見る」 | 動詞で始まる・行き先がわかる。比較表（`row.cta`）・固定バー（「楽天で見る」）と同じ「で見る」にそろう |
| 検索結果へ（Amazon、Yahoo!の個別ページが無いとき） | 「Amazonで探す」「Yahoo!ショッピングで探す」 | 商品ページではなく検索結果に行くことを正直に言う（「見る」だと商品ページに直接行くと期待させる） |
| 2行目：新しい価格 | 「10/11 06:33 時点の価格」 | 価格に時点を添える（スキル2章、1日1回取得なので「リアルタイム」とは書かない） |
| 2行目：古い価格 | 「3日前の価格」 | 既存の`staleLabel`と同じ言い方 |
| 2行目：価格なし | 「価格は販売ページで確認」／「検索結果で価格を確認」 | 価格が無い理由と次の行動 |
| 差額 | 「+¥1,200」 | 2番目以降は差額で（スキル2章）。「最安」「必ず」「お得」は使わない |

別案（今回は採らない）：A「Yahoo!で価格をチェック」（比較表と同じだが長い）、B「Yahoo!ショッピングへ」（短いが何をするかが弱い）。

## 5. 評価（design-critique の観点）
**全体**：主ボタンが一番目立つ階層は正しい。弱いのは他店の段で、押せるものに見えないこと。

| 指摘 | 重さ | 対応 |
|---|---|---|
| 他店ピルに動詞・矢印が無く、店名の一覧に見える（巡回メモの「ボタン無し」はこの見え方の結果と推測） | 中 | 動詞＋矢印（本案） |
| 価格の時点が購入ボックスに無い。古い価格は「（9日前）」が小さく出るだけ | 中 | 2行目に時点（本案） |
| 640px以上で2列にすると店名が切れる（`truncate`） | 小 | 1列に（本案） |
| 主ボタンの「（最安）」は比較した店の中での話だが、ボタンだけ読むと言い切りに読める | 中（表示・法令） | 次の候補（1回1か所のため今回は触らない）。例「楽天市場で見る」＋上の見出し「2店舗を比較した最安値」 |
| 比較表のYahoo!行で「…で確認」が2回出る | 小 | 次の候補（`StoreComparisonTable.tsx` 128行。価格が無いときは時点だけ足す） |

- 目に入る順（変更後）：価格 → 主ボタン → 他店ボタン（店名＋動詞）→ 比較表への案内 → PR表記。
- 一貫性：他店ボタンは比較表・固定バーと同じ「で見る」、同じ`CtaArrow`、同じ店マーク。
- アクセシビリティ：
  - ボタンの名前は「Yahoo!ショッピングで見る 価格は販売ページで確認」になる（店マークは`aria-hidden`のまま）。
  - 2行目・差額・古い価格の文字色は `foreground/65`＝白地で約5.2:1（AA 4.5:1以上）。`/60`は約4.46:1、`/55`は約3.8:1で届かないため使わない（`--foreground #14201b`・`--card #ffffff`から計算）。
  - 高さ48px以上（スキルの目安44px以上）。色だけで意味を伝えていない（差額は「+」と数字で示す）。
  - CLS：ボタンの中身はサーバーで描くので、表示中にボタンが動くことは無い（推測、計測は未実施）。
- 良い点：PR表記が購入ボックスの中・ボタンのすぐ下にある（`foreground/65`、STEP74で改善済み）。主ボタンは新しさ優先で古い価格の店を主役にしない（EXP-004）。

## 7. 測り方（押された場所別のクリック）
- 主な指標：商品ページのPVあたり、`placement = product_detail_cta_alt` のクリック数（店別：rakuten / yahoo / amazon）。
- 見る指標：`product_detail_cta`（主ボタン）と `product_sticky_bar`・`store_comparison` も並べ、他店ボタンが主ボタンのクリックを奪っただけでないか（購入ボックス合計が増えたか）を見る。
- 比べる期間：実施前14日と実施後14日（同じ曜日を含む）。PVが少なければ4週に伸ばす。
- 交絡：感謝祭（10/13〜10/19）はAmazonへのクリックが自然に増えると推測。判定では Amazon を除いた yahoo＋rakuten の件数も別に見る。EXP-001・004 と同じ期間に重なる。
- 合格の目安（推測の目標）：`product_detail_cta_alt`／PV が実施前より上がり、購入ボックス合計（cta＋cta_alt）が下がらない。件数が両期間とも20件未満なら「判定不能」と書く。
