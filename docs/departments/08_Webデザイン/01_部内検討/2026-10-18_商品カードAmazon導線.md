## (a) クリック率の暫定基準値 → 出せない(判定不能)
出典: 管理API kpi-summary 2026-10-18T15:04Z(docs/knowledge/kpi/2026-10-19.json)

| 項目 | 値 | 窓 |
|---|---|---|
| ショップクリック 直近7日 | 4(商品ページ副ボタン2・商品カード1・商品ページ主ボタン1) | 7日 |
| 前7日 | 10 | 7日 |
| 30日・累計 | 25・25 | |
| 店別(直近7日) | 楽天2・Yahoo!1・Amazon1 | |
| GA4 PV | 8 | 10/17の1日のみ |
| Search Console | 表示88・クリック4(CTR4.55%) | 10/15〜17の3日。検索結果での率で、サイト内のショップクリック率ではない |

- 計算式(固定): ショップクリック率 = 直近7日のshop_clicks ÷ 同じ7日のGA4 PV(全体)。場所別 = その場所のクリック ÷ 該当ページPV(商品ページ系は商品ページPV、トップ系はトップPV)。
- 現状は分子7日・分母1日で窓が違い、**判定不能**。4÷8=50%のような値は出さない(窓が違い、PVが極端に少ない)。
- 基準値を出す条件: GA4のPVが14日以上(同曜日を含む)貯まること。最短で、PVが取れ始めた10/17から14日後=10/31頃(推測)。それまでは「件数」を暫定基準にする(直近7日4件、前7日10件)。
- 件数の傾向: 7日4件は前7日10件・会社目標(月60)に対し大幅に遅れ。感謝祭(10/16〜19)中でも増えていない(推測: PVが極小で、クリック数がPVに比例するため)。
- 社長確認が要る: GA4の拡張計測(離脱クリック)がONか、GA4をDQ-6の分母にしてよいか。

## (b) 小さな改善: 商品カードにAmazon導線
仮説: 一覧カードの店ボタンは楽天だけ(placement=product_card、7日で1件)なので、Amazonで買いたい人の行き先が無く、離れてしまう。第2ボタン「Amazonで探す」を加えれば、カード経由のクリックが増える。見込み効果は推測で、PVが少なく、数字での判定は困難。

変更(1か所): `frontend/components/ProductCard.tsx`
- 主ボタン(楽天など)の下に、枠線の副ボタン「Amazonで探す →」(`btn-ghost`、高さ44px以上、全幅)を追加。主ボタンが既にAmazonの商品(affiliate_urlがAmazon)と、主ボタンが無い商品には出さない。
- リンクは既存の`getAmazonSearchUrl`(商品名のAmazon検索+アソシエイトタグ。CompareStrip・CompareTableと同じ仕組み)。`rel=sponsored`、`cta_type=affiliate_search`。
- 計測: placement=`product_card_amazon`(19字、上限30字内)。by_placementに別行で出るので、`product_card`と区別できる。
- 景表法・ステマ対策: 「最安」「価格」と書かない(Amazon価格は取得していない。商品ページの文言「Amazonで価格をチェック」より弱い「探す」を選んだ)。PR表記は一覧ページの既存のPrNoticeが上にある前提(新ページには追加しない)。
- 副ボタンの文字色は`text-foreground/75`(白地で約6.5:1の見込み。計算値は/65=5.2の延長で推測)。

## 注意・SEとの1本化
- ProductCardはトップ・一覧で使う。カードが縦に約56px伸びるため、トップのHTMLが少し増える(1商品あたりリンク1つ)。**トップ軽量化(SE部)とは、トップの商品カード数を減らす案が出た場合に影響する。カード数が決まってから適用を判断する(SEと1本化)。**
- 10/17のトップ刷新(TodayBuyShowcase)の小カードにはAmazon導線を入れていない(縦が伸びるため)。トップ最上部の効果を見てから判断。
- 同時に2つの変更を重ねると効果が分けられない。トップ刷新と同じ週に反映する場合、前後比較は`home_top_pick`+`product_card`+`product_card_amazon`の合計で行う。
