## 評価(design-critique の観点・ファイルで参照。コードと本番HTMLを読んだ範囲)
1. **今回新しくわかった点:上の6枚の根拠文が全部「記録上の差。販売店・条件の違いの可能性あり」**。例:¥24,750→¥9,900、¥178,200→¥118,800(本番HTML)。原因は `computeDeals` が値下がり率の**大きい順**に並べ、25%以上は注意書きに切り替わる(lib/deals.ts)ため、先頭6枚がちょうど「一番疑わしい差」になること。読者に見えるのは「% 値下がり」ではなく「違いの可能性あり」という注意書きで、押す理由ではなく押さない理由になる(推測)。
2. 同じ時点の /deals には、25%未満で%が表示される値下がりが14件(1.7〜20%)ある(本番HTML、11/22 00時台。/deals とガイドが同じ計算かは確認済みコード上のみ)。ガイドにはそれが1件も出ていない。
3. 流入の意図:検索表示は「ブラックフライデー 日程」系(推測)。日程を知りたい人が主で、買う意図は弱い。カードは本文の上にあるが、見出しが長い(「楽天市場の価格(PAR.の記録)で直近に値下がりした商品(Amazonの価格ではありません)」)。ボタンは楽天のみ(Amazonの受け口なし)。
4. 良い点:PR表記が最初のリンクの前にある、ボタンは44px(min-h-11)、「最安」を使っていない、placementで測れる。
5. 結論:押されない主因の候補は①PVが1/日と極端に少ない(最大)、②カードの根拠文が注意書き、③Amazon向けの受け口なし、④日程目的の閲覧者。①は画面では直せない。②は今夜のpatchで直せる。

## デメリット・リスク(メリットと同じ重さで)
1. 効果は測れない公算が大(PV約1/日。倍にしても判定に1群約450PV=knowledge 11/10)。「判定不能」で終わる可能性が高い。
2. 大きな値下がり(最大60%)の商品が6枠から外れる。読者の関心はむしろ大きい値下がりにある可能性(推測)。外れた分は /deals に残る。小さい値下がり(1〜5%)が先頭に並ぶと「値下がり」の見出しとして弱い(推測)。
3. 25%未満が6件未満の日は、従来どおり大きい差が後ろに混ざる(挙動は劣化しない)。
4. 値下がり率は「前回記録との差」で、BF中は記録の基準が動く。記録の日付は出ないままで、景表法上の根拠の弱さは残る(11/20記録と同じ)。
5. 本番反映前に監査(景表法・表示)が要る。カードの商品が日ごとに入れ替わり、前後比較の対象が変わる(測定の混ざり)。
6. 並びの変更は「ガイドの商品の選び方」の変更なので、総務(表記)が気にする可能性。
