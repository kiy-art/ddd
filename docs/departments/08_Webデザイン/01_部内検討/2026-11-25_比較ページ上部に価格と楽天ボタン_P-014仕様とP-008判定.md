## 0. 先に確かめた事実(コード:frontend/app/compare/[pair]/page.tsx、components/CompareTable.tsx)
- **比較ページには既に楽天ボタンがある。placement も既に `compare_pair`**(page.tsx 206行 `<CompareTable ... placement="compare_pair" />`)。ただし位置は表の**最終行**(CompareTable.tsx 178〜222行)で、表は `min-w-[640px]` の横スクロール(48行)。スマホ375pxでは「横に隠れ+縦の一番下」に押す場所がある。「押下0件」の原因の一つ候補(推測)。
- したがってP-014は「ボタンを新設」ではなく「**既にあるボタンを、最初の画面に移して見せる**」施策。**新しい場所の placement は `compare_pair_top`** とする(受信箱の `compare_pair` のままだと表の下の既存ボタンと区別できず、位置の効果が測れない)。判定は `compare_pair_top` と `compare_pair` の合計と、内訳の両方で見る。
- 「0件」の重さ(推測と計算):比較ページの検索クリックは14日で6(受信箱)。サイト全体のクリック率は14日で約4.5%(幅2.1〜9.4%、knowledge.md 11/18、kpi/2026-11-19.json系)。6訪問×4.5%=期待0.27件なので、**0件は偶然で十分起こる値**。UIの欠陥の証拠にはならない。位置が悪いのは構造上の事実(上記)だが、効くかは測れるかが別問題。

## 1. 仕様(どこを・どう変えるか)
### 1-1 置く場所と順序(page.tsx 185〜206行)
現在:PageHeader → 違いのポイント(カード) → PrNotice → 表(ボタンは最終行)
変更後:PageHeader → **PrNotice → 新ブロック「いまの楽天市場の価格」** → 違いのポイント → 表(ボタンは最終行のまま残す)
- PrNotice(PR表記)は新ブロックの**真上**へ移動(1か所のまま・重複させない)。最初の店ボタンより前にPRが来る(ステマ規制)。
- 新部品:`frontend/components/ComparePairPrices.tsx`(新規)。

### 1-2 見た目(ボタンの位置・大きさ)
- 見出し:「いまの楽天市場の価格」(h2・text-sm・太字)。「最安」「安い」とは書かない。
- 商品ごとのカード2枚を**スマホでも2列**(grid-cols-2 gap-3)。375pxでは外側px-6の内側327px→1枚約157px。カード内は上から:商品名(2行まで)→価格(font-num text-2xl)→時点(text-xs・/65)→ボタン。
- ボタン:カード幅いっぱい、高さ44px以上(min-h-[44px])、ピル型・緑(bg-brand・text-on-brand)、文字text-sm。表の下の既存ボタン(text-xs・py-3)より大きく=最初の画面で主ボタンになる。2枚とも同じ色・同じ大きさ(どちらかを推さない。最安の言い切りを避ける)。
- 押下は `TrackedCta`(event=cta_click、cta_type=affiliate_compare、**placement=compare_pair_top**)。rel="noopener noreferrer sponsored"、target=_blank。

### 1-3 文言(ux-copyの原則:動詞で始める・行き先が分かる・同じ役割は同じ文言)
| 場所 | 文言 | 理由 |
|---|---|---|
| 見出し | いまの楽天市場の価格 | 店名を明示。「最安」「最新」と言い切らない |
| ボタン | 楽天市場で見る ↗ | 既存の表(ctaLabel)と同じ「楽天市場で見る」。↗で外部に出ると分かる |
| 時点(価格あり) | 楽天市場・11/25取得 | 価格のすぐ下。日付はJST。「リアルタイム」とは書かない(learnings.md 53行・景表法) |
| 価格なし | 価格は販売ページで確認 / 最後に取得した日:11/18 | 数字は出さない。最後の取得日は事実なので出せる |
| 注記(ブロック下・text-xs・/65) | PAR.が楽天市場から取得した価格です(1日1回更新)。送料・ポイント・在庫は含みません。購入前に販売ページでご確認ください。取得から3日を過ぎた価格は表示しません。 | 取得頻度は実態どおり(SE 11/8の表記修正と整合)。比較に入れていない要素を明示 |
| スクリーンリーダー | 「楽天市場で{商品名}を見る(広告・別タブで開く)」 | 同じ文言のボタンが2つあるので商品名で区別。アクセシビリティ |

### 1-4 価格の鮮度(時点表示)
- 商品ページと同じ規則を再利用:`getShopOffers`(lib/shopOffers.ts)。楽天のURL+現在価格あり+**取得から3日以内(OFFER_FRESH_DAYS)**のときだけ数字を出す。時点は price_history の最後の recorded_at(商品ページ page.tsx 174行と同じ取り方)。
- 3日超:数字を出さず「価格は販売ページで確認」(商品ページは3〜7日を小さく出すが、ここは2枚並べて比べる場面なので、古い数字は出さない方が誤認が少ない=推測)。ボタンは出す(売り場への導線は価格が無くても有効)。
- 差額・「どちらが安い」はこのブロックには出さない(既存の「違いのポイント」に現在価格の差が文章であり、重複と言い切りリスクを避ける)。

### 1-5 価格が無いとき
| 状態 | 表示 |
|---|---|
| 片方だけ価格が新しい | 新しい方は価格+時点、古い方は「価格は販売ページで確認」。ボタンは両方 |
| 両方古い/無い(楽天URLは有る) | 2枚とも「価格は販売ページで確認」+ボタン。ブロックは残す(ボタンが主役) |
| 片方が楽天URL無し | その枚のボタンを「価格推移を見る」(商品ページへの内部リンク・枠線ボタン・計測しない)に差し替え |
| 両方とも楽天URL無し | ブロックごと出さない(null)。表の下の既存導線のみ |
| Yahoo!・Amazon | **出さない**。Yahoo!は営業の目標「報酬が付かないリンク459/0」が未達で提携未完了(事実.md 11/25)。Amazonは価格を取得しておらず検索リンクのみ(CompareTable 204行コメント)。3店並びは価格なし店が混ざり価格.com型の「最安+平均」には届かない |

### 1-6 PR表記・景表法・規約
- PR表記:既存の `PrNotice`(PRバッジ+本文、text-sm・/80)をそのまま新ブロックの上に。薄くしない・小さくしない(SKILL 5章)。
- 景表法:「最安」「必ず」「リアルタイム」を使わない。価格は時点つき。取得頻度を実態どおりに書く。送料・ポイント非含有を注記。
- 規約(楽天アフィリエイト):画面の表示価格の鮮度・誤認の防止という論点がある。**規約本文は今夜未確認**(総務に確認を依頼)。価格の取得時点を明示し3日超を出さない設計は、その懸念を小さくする側(推測)。
- 巡回メモ(価格.comマガジン:製品ごとに3店ボタン固定順+平均/最安併記、2022年10月記事)は考え方のみ。「最安」併記は価格の鮮度が落ちると誤認になるため**採用しない**(本文・画像・配色は写さない)。

### 1-7 スマホ375pxでの見え方(コードからの推測。実機未検証)
- 最初の画面(PageHeader の下):PR表記(2〜3行)→見出し→2枚のカード(価格・時点・ボタン)。PageHeaderの高さが未確認のため「最初の画面に入るか」は未検証。入らなくても、表の最終行よりは大幅に手前。
- 商品名が長い場合は2行で切る。2列でボタン文字(約7字・text-sm)は約157px−padding内に収まる(推測)。長い価格(¥100,000台)はtext-2xl×6文字で約100px(推測)。
- CLS:価格はサーバー側で描画。ボタンが後から動かない。

## 3. デメリット・リスク
1. **効果はほぼ測れない**:比較ページの訪問は14日で6クリック程度(受信箱)。7日後(12/2)の訪問は約3(推測)で、率の差は**判定不能になる公算が非常に高い**。12/2に判定できるのは「`compare_pair_top` に押下が出るか(計測が通るか)」まで。
2. 見込み(推測):月の訪問約13(6÷14×30)×クリック率4.5%=約0.6件、強気15%で約2件。EPC仮値6円(learnings.md 36行)で月約4〜12円。月1万円の利益との距離は0.1%未満。**収益のための施策ではなく、「位置を変えたら押されるか」を最小の費用で確かめる学習用**。
3. 「違いのポイント」(本文・SEOの主な内容)が画面の下に下がる。検索流入の滞在・直帰への影響は未測定(推測:ブロック高さは約200px)。
4. PrNoticeを上に動かすので、ページ最上部の見た目が変わる(広告表示が目に入りやすくなる=クリックをわずかに下げる可能性)。ステマ規制上は安全側。
5. 価格が3日超だと「価格は販売ページで確認」だけになり、価格を見せる狙いが薄れる(楽天の更新は1日1回・11/25の日次ジョブで709件更新・232件スキップ=事実.md。全商品が3日以内とは限らない)。
6. 表の最終行の既存ボタンと二重に同じ商品の同じ店ボタンが出る(押し先は同じ)。計測は placement で分けるが、「上を押す人は下でも押す人」の重複はなく合計で比べる必要がある。
7. 楽天の表示規約は未確認(総務確認待ち)。patch は tsc・375px・本番表示を未検証。
8. P-008(/popular)の測定と重ならない:触るのは /compare/[pair] と新部品のみ。ガイド・/popular・ProductCard は触らない。
