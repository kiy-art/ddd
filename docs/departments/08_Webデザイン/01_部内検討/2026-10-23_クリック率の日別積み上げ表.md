## 2. 10/31に基準値を出す手順
1. 窓: 10/17〜10/30の14日(同曜日を2回含む。スキル追加点検の「14日以上」)。
2. 分母: 上表の日別PV。欠けた日は「未取得」のまま合計し、取れた日数を併記する(補完しない)。
3. 分子: 10/31朝のkpi-summaryの shop_clicks.total から10/16時点の25を引く(窓の終端が10/30夜の取得になるか要確認)。場所別は last_7d_by_placement を週次で足す。
4. セール期間(プライム感謝祭10/16〜19・楽天マラソン10/14〜17)は別注記し、窓の前半に含まれる点を併記。
5. 欠けを減らす提案(実行は全体統括): 日次スナップショットをGA4の日付ごとに毎日保存する。10/16・10/21のような欠けと重複を防ぐ。

## 3. リスク・デメリット
- 欠け2日と重複で、率は「取れた日のPV」基準になり過小/過大が混ざる。クリックが月数件のため、1件増減で率が大きく動く。
- 率が出ても施策の効果比較(前後)は判定不能になりやすい。基準値は「現状の目安」であり、改善の証明ではない。
- 効果の見込み: 測定準備のため直接の収益効果なし。

## 4. 知識への追記案
- 日次kpi jsonのga4は日付が飛ぶ・重複するため、日付(snapshot_date)で重複を除いて積み上げる。
