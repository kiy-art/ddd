## 2. 受信箱P-015:セールガイド上部の値下がり枠の「選び方」の基準案(コードはSE)
### 今の仕組みと問題(コードと公開APIで確認)
- セールガイド(prime-appreciation-sale-2026-golf)の枠は `featured.kind="price_drops"`・カテゴリ指定なし(frontend/lib/guides.ts 76行)。`getProducts()` は件数指定なしのため、APIの既定50件(並びは30日平均比の値下がり率の大きい順。backend/app/crud.py list_products)だけを見て、`computeDeals` が「前回記録より下がった」順に6件出す(page.tsx 33〜39行、deals.ts)。
- 11/28 0:07 JST の再現:今の枠の6件はすべてボール。前回記録との差は44〜66%(ID141 19,800→6,660円、ID179 9,896→4,950円 など)。ID179 は商品URLが「3set」の掲載で、前回記録との差は出品・セット違いの可能性が高い(推測)。全503件で見ると前回記録より下がった商品は23件(ボール14・ドライバー2・距離計2・グローブ2・ウェッジ1・パター1・その他1)。
- 過去の試行:experiments.csv に値下がり枠の選び方の施策は無い。25%以上の差は%を出さない処理(deals.ts の DROP_VERIFY_PERCENT、SE監査2026-10-25)がある。

### 基準案(上から順に当てる)
1. **全商品から選ぶ**:既定50件ではなく、掲載全件(またはカテゴリごと)から候補を取る。
2. **記録が十分**:history_span_days が14日以上で、30日平均(average_price)がある。
3. **値段が安定した後に下がった**:前回記録(previous_price)が30日平均の±10%以内。=前回の値段がふだんの水準だったもの。
4. **出品違いを除く**:前回記録との差が3%以上25%未満。かつ30日平均との差(price_change_percent)が-25%より小さい幅。25%以上は出品・セット・クーポン違いの可能性として枠に出さない(%表示を隠すだけの今の扱いより厳しくする)。
5. **今の値段が平均以下**:current_price ≤ average_price(一時的に上がった後の戻りを「値下がり」と見せない)。
6. **偏りを防ぐ**:同じカテゴリは最大2件(セールガイドはカテゴリ横断のため)。並びは前回記録との差の大きい順。
7. **審査待ちを出さない**:pending_review=false(今の公開APIは公開分のみのはず。SEが確認)。
8. **0件なら空のまま**:基準に合う商品が無い日は、無理に埋めない(既存の方針「実在しない値下がりを演出しない」guides.ts 312行と同じ)。
