# 02_営業

- エージェント：`dept-sales`
- 役割：ASP・広告主との提携、報酬率の比較、収益化できていないリンクの洗い出し、新しい収益の柱。
- 主なKPI：EPC、収益化できているショップリンクの割合、提携先の数
- 担当する事業：全事業共通（001_Par.Golf、今後の002、003…）

## このフォルダの使い方
- `knowledge.md`：部署の学び。1行1件。`- YYYY-MM-DD [事業番号] 内容(根拠: 出典)`
- `01_部内検討/`：毎日の部内検討の記録。`YYYY-MM-DD_件名.md`。議題が無い日は書かず、`knowledge.md`にも足さない（「検討事項なし」は当日の報告に1行だけ）。
- `02_会議提出/`：代表者会議の意見書。1回の会議で1ファイル`YYYY-MM-DD_代表者会議.md`（議題は節）。**出したあとは書き換えない**（考えが変わったら「会議後」欄に追記）。

## 決まり（docs/departments/README.md）
- 部内検討のあいだは、他部署のフォルダを読まない。読んでよいのは事実のデータ（`docs/knowledge/`の台帳・`market.md`・`learnings.md`、`kpi/`）と過去の議事録（`00_代表者会議/議事録/`、`docs/meetings/`）だけ。
- 書いてよいのは、このフォルダの中だけ。
- 公開リポジトリ。書かないもの：APIキー・トークン・パスワード、購読者や問い合わせ者のメールアドレス・氏名・問い合わせ内容、社長の氏名・住所・口座、ASPの管理画面の画面写真やアカウントID、ASPとの個別の条件（特別単価など未公開の契約条件）。金額は、月の合計とASPごとの発生・確定の合計までは書いてよい（個別の取引・単価・未公開の条件は書かない）。受信箱にこれらがあれば写さない。
