## 2. patchの中身(`2026-11-25_新商品のproduct_url空にする_重複判定維持.patch`)
- 対象:backend/app/discovery.py、backend/tests/test_discovery.py(`git apply --check` は通過済み。構文は py_compile で確認)。
1. 新関数 `_plain_url_of(affiliate_url)`:楽天アフィリエイトURLの `pc=` の中身(素の商品URL)を取り出す。他の形式・None は None。
2. `discover_new_products` の `existing_urls` に、既存商品の affiliate_url から取り出した素URLも加える(289行の直後)。→ product_url が空でも、同じ楽天ページの再発見を URL 判定で止められる。
3. 新商品の作成時:楽天IDが設定されていてアフィリエイトURLに包めたときだけ `product_url=None`。ID未設定のときは従来どおり product_url も affiliate_url も素URL(=包めない場合に何も残らなくなるのを防ぐ)。
4. テスト2本を追加:(a)ID設定時に product_url が None・affiliate_url が楽天アフィ形式、かつ「別タイトル・同URL」の2回目が0件になる(URL判定だけで止まることを確認する作り)、(b)`_plain_url_of` の取り出し。
- 画面への影響:frontend/lib/shopRows.ts 208行は `product.product_url &&` で判定しており、null なら「メーカー公式サイト」行は出ない(コードで確認。画面の実測は未実施)。v2 patch(isRedundantPlainLink)とは干渉しない。
