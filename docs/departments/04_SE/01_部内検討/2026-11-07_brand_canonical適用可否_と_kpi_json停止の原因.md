## 日次kpi jsonが10/29で止まっていた原因
### 事実(根拠: git log、docs/knowledge/kpi/ のファイル、kpi_ledger.csv)
- jsonの存在日: 10/5、10/15〜10/23、10/25〜10/29、その後 11/5〜11/8。10/30〜11/4は無し。
- 10/29までのjsonは、10/29 23:23Zの1コミット(e57ffa2)でまとめて追加されている。それ以前はこのディレクトリが未追跡だった形跡(推測)。
- 台帳の11/1・11/2行は、台帳だけを変更するコミット(d11a38b、8c9e953)で、jsonが伴わない。11/2行のnoteは「手動転記」。スクリプトは台帳とjsonを両方書くので、この2行はスクリプトを通っていない(推測)。
- 11/5以降は json と台帳が毎日1コミットで揃っている(8e41888・696db23・4e9e465・3426d9e)。kpi_snapshot.py のhttpx無し対応(urllib代替)は11/5 15:11Zに反映(6b8b34b)。つまり11/5〜11/6のjsonはhttpx対応の反映前に作れており、**httpx不足だけでは全期間は説明できない**。
- 台帳の欠け日(10/24、10/30、10/31、11/3、11/4)のうち、10/30〜11/4のjson無しの6日間は実行履歴(ルーチンのログ)が残っておらず、コードと台帳からは理由を区別できない(未確認)。
### 推測(複数)
1. 10/30〜11/3の夜は、実行環境にhttpxが無い・トークンが無いなどでスクリプトが走らず、事実記録だけが手で書かれた。
2. 走ったがjsonをコミットする経路(自動取り込み)が欠けた。
- 再発防止(提案): 欠測日は台帳に「欠測: 理由」行を必ず1行残す(日付が飛ぶと気づけないため)。今は11/5以降、毎日揃っているので緊急ではない。確認手段: 14日後(11/21)に台帳の日付とjsonの日付が一致しているか数える。
