## 1. 事実(コードで確認)
- 枠は `app/guides/[slug]/page.tsx loadFeaturedProducts`。category 無しの price_drops(=セールガイドのみ。ボールガイドは category:"ball" で別経路)は `getProducts()` を引数なしで呼ぶ。
- `getProducts()` は backend 既定 limit=50(routers/products.py 43行)、並びは price_change_percent 昇順=平均より安い順(crud.py 79行)。つまり**最初の50件がそもそも偏る**(市場は ball の下がった商品が最多:ball 17/96、driver 13/95、iron 13/51 ほか、11/28事実ファイル)。ボール6件の原因はここと推測(本番の実データは未確認)。
- 商品一覧は価格履歴を返さない(ProductDetail のみ)。使える項目は current / previous / average(30日平均・現在値を含む)/ lowest / history_span_days。`previous_price` は「直前の記録1点」(crud.py 281行)で、出品が入れ替わっても1点前と比べるだけ。
- `computeDeals` は previous > current なら全件。25%以上は既存の `DROP_VERIFY_PERCENT` で割合表示を伏せるだけで、枠からは除かれない。

## 2. 変更の要点
1. `lib/deals.ts` に `computeStableDeals(products, limit)` を追加(`computeDeals`・`dropLabel` は無変更=/deals・トップ・ボールガイドは影響なし)。
   - 下がり幅 3%以上25%未満(25%以上は別出品の可能性が高いので枠から除外)
   - 履歴7日以上、直前価格が30日平均の±5%以内(2つの出品の間で行き来する商品は平均から離れるので除外)、現在値が30日平均より3%以上安い
   - カテゴリごとに最大2件のラウンドロビン(ボールだけで埋まらない)
2. 件数が足りないとき:厳しい条件で3件未満なら、緩い条件(3〜25%未満)で3件まで補う。それでも0なら既存の「条件に合う商品がありません」表示(空のまま壊れない)。6件を埋めるための水増しはしない=**3〜6件に減りうる**。
3. `page.tsx`:category 無しのときだけ `getProducts({ limit: 300 })` + `computeStableDeals`。キャプションは既存の `dropLabel`(前回記録→現在・出品違いの可能性を併記)。

## 3. できないこと・限界(デメリット)

- 件数が減る(最低3件、0件もありうる)。ガイドの上部が短くなるとクリック数が減る可能性。
- 判定期間12/4までは BF終了(Amazon 12/7)・楽天スーパーSALE予想(12/4〜、公式未発表)と重なり、値動きそのものが変わるため、前後比較は交絡する。
