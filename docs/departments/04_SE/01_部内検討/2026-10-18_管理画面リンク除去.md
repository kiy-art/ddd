# 2026-10-18 サイト共通ナビから/adminへの公開リンクを除去

## 目標との関係
目標=エラー週1,000件以下(DQ-6)。今週は0から数え直し。直接の削減効果は小さい(推測)。ただし公開ページ全部から/adminへのリンクが出ていたため、クローラーや Next.js の Link 先読みで /admin の JS が取得され、不要な通信・露出になっていた(推測)。これを止める。

## 確認したこと(コード)
- 公開リンクの出どころは `frontend/components/SiteNav.tsx` の2箇所のみ(モバイルのシート `SHEET_FOOTER_LINKS` と、PCサイドバー下部)。トップページ(app/page.tsx)のファイルではない=WebデザインのUI刷新と競合しない。
- 認証:`frontend/app/admin/layout.tsx` が `useAdminAuth` で status を見て、未認証は `AdminLoginForm` のみ表示(クライアント側ゲート。データはAPI `/api/admin/*` のトークンで守られる設計。API側の検証は今回未確認)。管理画面の認証は変更していない。
- `frontend/app/robots.ts` は `/admin` を disallow 済み。ただし /admin に noindex の meta は無い(layoutが"use client"のためmetadataを出せない)。

## 変更(レベルA、元に戻せる)
- `frontend/components/SiteNav.tsx`:`SHEET_FOOTER_LINKS` から `{ href: "/admin", label: "管理画面" }` を削除。PCサイドバー下部の `<Link href="/admin">管理画面</Link>` を削除。
- 運営者は /admin を直接URLで開く(ブックマーク)。管理画面内のナビは別layoutで影響なし。

## 確かめてほしい点(議長)
- tsc(`next typegen` 後)・lint・ビルドが通ること。
- PC/モバイルで、フッター側リンクが「お気に入り〜プライバシー」までで崩れないこと。
- ナビ周りのE2E/テストに「管理画面」リンクを期待するものが無いこと(grepではapp/components/lib内に他の参照なし。テスト置き場は未確認)。
- 本番で `curl https://par-gear.com/ | grep -c 'href="/admin'` が0になること(測り方)。

## 提案止まり(要レベルB以上の検討)
1. /admin 系に noindex を付ける:`app/admin/` に server component の薄い layout か `page.tsx` 側 metadata が必要(現layoutはclient)。robots disallow だけだと外部リンク経由でURL自体は索引に出得る。工数 約1h±30%。
2. (b) 商品スラッグの販促文言除去:新規のみ生成ロジック変更なら元に戻しやすいが、スラッグ生成箇所は未調査。既存URL変更・リダイレクトは戻しにくいので提案止まり。次回調査(調べる1h・作る2h・テスト1h、±50%)。
3. トップHTML 588KB(推測で重い):Webデザインのトップ刷新後に、同梱データ量を測り直す。
