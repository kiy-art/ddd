## 2. 新規案の5項目評価:「モデル指定の検索語で自動登録された同モデル・店違い商品を、1モデル1ページにまとめる」(量産の逆=整理の案)
背景:11/17の日次ジョブで、Spider ZTパター20件(公開10)とスリクソンZXアイアン20件(公開11)が登録。同じモデルが店・シャフト違いで別商品として並ぶ(受信箱8、SE・Webデザイン宛)。

| 項目 | 内容 |
|---|---|
| 見込み利益(根拠) | 直接の金額は出せない(未取得)。守る効果:一覧の見づらさ・薄い重複ページの増加を防ぐ。集客を動かす効果:小(公開は掲載449件の約5%=21件相当、事実.md)。クリック効果は「推測」で標準でも月0〜数十円。必要売上(約15,600円)の1%未満 |
| 最初の収益までの期間 | 収益は期待しない。効果は一覧の見やすさとして公開後すぐ(コード変更の監査・適用後) |
| 初期/月額費用 | 0円(コード変更はSEが.patch、DB統合は dry-run→監査)。作業は中(タイトル整形+上限設定+既存の統合) |
| リスク | 統合で既存URLが消えると、検索・内部リンクが切れる(301が必要)。店別の価格・クリック履歴を失う恐れ。DB統合は元に戻しにくく、誤統合(別仕様を同一視)で価格表示の誤りになりうる=景表法リスク。自動の名寄せは誤差が出る |
| 既存資産の流用度 | 高。title_cleaner・discovery.pyの既存ロジックを流用 |

- 3軸の比較(費用0円案の追加点検):守る効果=あり/集客を動かす効果=小/作業量=中。
- programmatic-seoの判断(スキルの「データが浅いか」「サンプルで薄くないか」の基準):このページ群はモデル名+店違いのデータで、1ページあたりの独自の情報が増えていない。**増やす方向は不採用**。検索語からの自動追加は、上限(1語あたり数件、カテゴリ上限20件を1モデルで使い切らない)を付けるのが先。比較ページ約650件をsitemapから外した前例(10/28会議)と同じ型の「量より質」の判断。
- 3案の比較:A 何もしない=費用0・作業0・重複が増え続ける。B 上限だけ(追加時)=作業小・既存の重複は残る。C 上限+同モデル統合(dry-run→監査)=作業中・誤統合リスクあり。推奨はB→(dry-runで誤統合が0件と確認できれば)C。
- 撤退/戻す基準:統合後14日(12/初旬)で検索表示・ショップクリックが統合前の3日平均より下がる、または誤統合が1件でも見つかればロールバック。実施の前提:統合前の各商品のクリック・表示を台帳に残す(商品別台帳=案Cが先)。
- できなくなること:SEの今週の作業時間は、BF窓の障害対応(Yahoo 429、error監視)と取り合う。BF開始(11/19〜)の直前の本番DB変更は避ける(推測)ため、DB統合は11/26再判断の後が安全。
