# 代表者会議（全部署会議）

毎週水曜・土曜の夜、部内検討のあとに続けて開く。このフォルダに書くのは議長（全体統括）だけ。

> 公開リポジトリ。書かないもの：APIキー・トークン・パスワード、購読者や問い合わせ者のメールアドレス・氏名・問い合わせ内容、社長の氏名・住所・口座、ASPの管理画面の画面写真やアカウントID、ASPとの個別の条件（特別単価など未公開の契約条件）。金額は、月の合計とASPごとの発生・確定の合計までは書いてよい（個別の取引・単価・未公開の条件は書かない）。受信箱にこれらがあれば写さない。議長は全体統括。監査は立ち会い（賛否は言わない）。

## 進め方
1. **議題の確定**（議長）：受信箱・判断ボードの回答・部内検討の記録・KPIの台帳から、議題を最大3件決め、`議題/YYYY-MM-DD.md`に書く（テンプレート：`_テンプレート/議題.md`）。議題は事実だけで書き、議長の意見は書かない。
2. **意見書の提出**（各部署、並行）：自分の部署のフォルダと事実のデータだけを見て、意見書を`<部署>/02_会議提出/YYYY-MM-DD_代表者会議.md`に1ファイルで出す（議題ごとに節）（テンプレート：`_テンプレート/意見書.md`）。**出したあとは書き換えない。** 関係が無い部署は「意見なし（理由1行）」で出す。
3. **一度に並べる**（議長）：全部署の意見書がそろったら、意見書だけをローカルにcommitし（「意見書提出 YYYY-MM-DD」）、そのハッシュを議事録に書く。そのあと、発言順のとおりに一度に並べる。そろう前に一部だけを他部署に見せない。
4. **相互の質疑**（1回）：並べた意見書を全部署に一度に渡し、反論・質問・修正案を1回だけ受ける。元の意見書は直さず、意見書の「会議後」欄に追記する。
5. **議長の案**：全体統括は、自分の案を最後に出す。「見込み利益 × 確度 ÷ 工数」で順位をつける。
6. **偏りチェック**（監査）：下の表で確認し、`10_監査/02_会議提出/YYYY-MM-DD_代表者会議.md`に書く（議長が議事録に写す）。不合格の項目があれば、議長が直してから結論にする。
7. **結論**：多数意見、割れた点、少数意見・反対意見（理由つき）、条件、決裁レベル（A／B／C）を書く。レベルAかつ監査合格のものは実行する。レベルBは承認依頼書（`docs/approvals/`）と判断ボードへ。
8. **議事録**：`議事録/YYYY-MM/YYYY-MM-DD.md`（1回の会議で1ファイル）（テンプレート：`_テンプレート/議事録.md`）。
9. **持ち帰り**：各部署は翌晩の部内検討で、結論を自分の`knowledge.md`の「代表者会議から持ち帰ったこと」に1行で書く。

## 発言順の記録
発言順は、前回の先頭の次の部署から始める（一巡したら02_営業に戻る）。全体統括は常に最後。監査は発言しない。

| 日付 | 先頭の部署 | 順番 |
|---|---|---|
| （初回は02_営業から） | 02_営業 | 02営業 → 03マーケ → 04SE → 05人事 → 06経理 → 07経営企画 → 08Webデザイン → 09総務 → 01全体統括 |
