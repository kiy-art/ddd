# 承認依頼 #001：AI会社の運営モデルと決裁権限の開始（2026-10-04）

- 状態: 未決
- お願いしたい判断：承認 / 一部承認（番号を指定） / 却下
- 内容：
  - `docs/ai_company_operating_model.md`の組織（7部署＋全体統括＋監査）と決裁権限（A：社内で実行・事後報告／B：社長承認／C：社長のみ）で、運営を始める。
  - 社長の作業を減らすため、下記1〜4の権限をAIに預けてほしい。
- おすすめ：全項目承認。社長の作業は「承認依頼への回答」と「本人確認が必要な登録・契約」だけになる。

## 承認をお願いしたい項目

1. **決裁権限表の適用**
   - レベルA（サイトの改善・不具合修正・コンテンツ・SEO、dry-runで確認でき元に戻せる本番データ処理）は、監査を通ればAIが実行し、事後報告する。
   - これに合わせて、safe-db-migrationの「本番への適用は社長がボタンを押す」を「監査合格後はAIが管理APIで実行できる」に改める。元に戻せない削除は、引き続きレベルB。
2. **管理APIのトークンを作業環境に登録**
   - 何に使うか：本番のクリック数・エラー・日次ジョブの状態の読み取りと、レベルAのデータ処理。
   - 登録のしかた：セッション画面上部のクラウド環境メニュー →「Edit」→ 環境変数に`PAR_ADMIN_API_TOKEN`を追加（値はRenderの`ADMIN_API_TOKEN`と同じもの）。**チャットには貼らないでください。**
3. **（任意）RenderのAPIキーを作業環境に登録**
   - 何に使うか：環境変数の設定・再デプロイ・ログ確認。これまで社長にお願いしていたRender画面での作業を、AIが代わりに行える。
   - 登録のしかた：環境変数`RENDER_API_KEY`（RenderのAccount Settings → API Keysで発行）。
4. **通信先の許可**
   - 内容：同じ「Edit」画面の「Network access」で「Custom」を選び、`golf-deals-backend.onrender.com`、`par-gear.com`、`api.render.com`を「Allowed domains」に追加する。既定の許可先はそのまま残す。
   - 理由：現在はこれらへの接続が止められていて、AIが本番の状態を確認できない。
5. **週次の経営会議の定期実行**
   - 毎週月曜 9:00（日本時間）に、AIが自動で会議（`/ai-company-meeting`）を開き、議事録と承認依頼を作る。
   - 社長への報告は、このチャットと議事録（`docs/meetings/`）。
   - 費用：Claude Codeの利用のみ（事前承認済み）。新たな費用はかからない。

- 見込み効果：社長の作業が減り、改善の回転数が上がる（週1回以上の改善実行）。収益への効果は、施策ごとに会議で測って報告する。
- 費用：0円（1〜5のどれも新たな契約は不要）。
- リスクと対策：
  - **本番データの誤操作**：dry-run → 監査 → 実行の順を必須にし、元に戻せない操作はレベルBにする。
  - **トークンの漏えい**：作業環境の環境変数にだけ置き、出力・ファイル・コミットには書かない（監査のチェック項目）。
  - **AIの判断ミス**：週次報告で実行内容を全件開示する。悪化した施策は、自動または社長の指示で元に戻す。
- 監査意見：
  - 権限の範囲は「元に戻せる操作」に限られており、費用・契約・削除は社長の決裁に残るため、妥当。
  - 監査は同じAIモデルの別エージェントによるもので、人間の第三者監査ではない。法的に重要な判断（規約・個人情報）は、必要に応じて専門家への確認を推奨する。
- 期限：なし（承認された項目から順に開始）
