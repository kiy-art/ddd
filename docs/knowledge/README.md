# 会社の知識（データ・ドリブン経営の記録）

経営判断の根拠にするための蓄積（`docs/ai_company_operating_model.md` 1.2）。会議のたびに更新する。

| ファイル | 中身 | 更新する人・タイミング |
|---|---|---|
| `kpi_ledger.csv` | KPIの台帳（1日1行）：掲載商品数・ショップクリック・検索表示/クリック/CTR/順位・PV・通知登録・エラー・月次売上 | 経営会議で`backend/scripts/kpi_snapshot.py`が自動で追記する。売上は経理が、社長から共有されたASPの数字を手で記入する |
| `kpi/YYYY-MM-DD.json` | その日の`/api/admin/kpi-summary`の全項目（台帳の元データ） | 同上 |
| `experiments.csv` | **PDCAの台帳**（1施策1行）：計画（仮説）・実行・評価（比べる前後の数値と判定）・改善（継続／拡大／修正／撤回）・学び。**失敗・効果なしの施策も消さずに残す** | 施策を実行したとき（全体統括）、効果を測ったとき（人事・経理） |
| `experiments.md` | 上の台帳の詳しい説明（背景・実施の中身・測定の注意点） | 同上 |
| `auto_pdca_ledger.csv` | サイトの自動改善（タイトル変更・並び替えなど）の判定結果の件数：改善・悪化・未判定 | 経営会議で`kpi_snapshot.py`が自動で追記する |
| `market_ledger.csv` | 市場の動き（自社の価格データから）：カテゴリ別の値下がり・値上がり商品数、変化率の中央値、新商品数 | 同上 |
| `market.md` | トレンド・市場状況（外部の情報）：新モデル、季節の需要、セール、ASPのキャンペーン、競合。出典と確認日つき | 経営会議で、マーケ・営業が調べて追記する |
| `investments.csv` | **投資の台帳**（承認された費用1件1行）：何のための投資か・見込み・損益分岐・測定日・撤退の基準・実績・判定。見込みと実績のずれを、次の投資判断に使う | 承認時（経営企画）、測定日（経営企画・経理） |
| `president_preferences.md` | **社長の判断基準・方針**。承認依頼と提案は、これに合わせて作る | 社長から方針が示されたとき（全体統括） |
| `learnings.md` | 確かめた事実と学び（出典・日付つき）。次の提案の根拠にする | 会議で新しくわかったとき |

**ルール**：
- 推測は書かない。書くときは「推測」と明記する。
- 個人情報（メールアドレスなど）と秘密情報（キー・トークン）は書かない。
- 数字には、取得元と取得日を残す。
- **PDCAの記録は消さない**。うまくいかなかった施策も、次の判断の根拠になる。撤回した施策は、`act_decision`を「撤回」にして残す。
- 施策の効果を判定するときは、同じ期間の市場の動き（`market_ledger.csv`・`market.md`）と比べる。市場全体が動いただけのものを、施策の効果としない。

**社長室との連絡**：Notionの「PAR. 経営ボード」（非公開）。社長室からは「受信箱」、Codeからは「報告」に書く。正式な記録は、このリポジトリに置く。

**データの所在**（ここにあるのは要約で、元データはこちら）：
- 本番DB（Render Postgres）の次の表。管理API（`/api/admin/*`）経由で読む。
  - `affiliate_clicks`：ショップへのクリック。押された場所付き
  - `page_metrics_snapshots`：GA4・Search Consoleの、ページ別の日次数値
  - `ai_optimization_actions`：自動改善の施策と効果判定
  - `price_history`：価格の推移
- 売上：各ASPの管理画面（楽天・Amazon・バリューコマース）。AIは直接見られないので、社長からの共有が必要。
