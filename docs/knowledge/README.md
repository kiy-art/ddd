# 会社の知識（データ・ドリブン経営の記録）

経営判断の根拠にするための蓄積（`docs/ai_company_operating_model.md` 1.2）。会議のたびに更新する。

| ファイル | 中身 | 更新する人・タイミング |
|---|---|---|
| `kpi_ledger.csv` | KPIの台帳（1日1行）：掲載商品数・ショップクリック・検索表示/クリック/CTR/順位・PV・通知登録・エラー・月次売上 | 経営会議で`backend/scripts/kpi_snapshot.py`が自動で追記する。売上は経理が、社長から共有されたASPの数字を手で記入する |
| `kpi/YYYY-MM-DD.json` | その日の`/api/admin/kpi-summary`の全項目（台帳の元データ） | 同上 |
| `experiments.md` | 施策と結果の記録（仮説 → 実施 → 測定 → 学び） | 施策を実行したとき（全体統括）、効果を測ったとき（人事・経理） |
| `learnings.md` | 確かめた事実と学び（出典・日付つき）。次の提案の根拠にする | 会議で新しくわかったとき |

**ルール**：
- 推測は書かない。書くときは「推測」と明記する。
- 個人情報（メールアドレスなど）と秘密情報（キー・トークン）は書かない。
- 数字には、取得元と取得日を残す。

**データの所在**（ここにあるのは要約で、元データはこちら）：
- 本番DB（Render Postgres）の次の表。管理API（`/api/admin/*`）経由で読む。
  - `affiliate_clicks`：ショップへのクリック。押された場所付き
  - `page_metrics_snapshots`：GA4・Search Consoleの、ページ別の日次数値
  - `ai_optimization_actions`：自動改善の施策と効果判定
  - `price_history`：価格の推移
- 売上：各ASPの管理画面（楽天・Amazon・バリューコマース）。AIは直接見られないので、社長からの共有が必要。
