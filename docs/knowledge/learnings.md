## インフラ・運用
- 楽天の検索APIのキーワード：1語ごとに「半角2文字以上、または全角1文字以上」（STEP40）は本番の結果と食い違う。**全角の英数字（Ｓ）・かな（ス・の）の1文字の語も不可、漢字1文字（白・入・旗）は可**（2026-10-06：全角に変えた81件はすべて失敗、かな3件も失敗、漢字1文字を含む成功12件）。これに加えて、記号だけの語（「」［］・単独の「ー」・/ など）も「keyword is not valid」になる。長さは文字数で128未満。2026-10-04の184商品で確認（例外0件、SE）。→ STEP74で修正。
- 楽天の400の本文には`wrong_parameter`が入るため、自動修復が「設定の確認が必要」と誤って判定していた（STEP74で修正）。
- Yahooの429は、1回の実行で約30回呼ぶと出る。18分あければまた約30回呼べる。「その日の上限」ではなく短時間の上限の可能性が高い（推測、SE）。
- YahooのアフィリエイトURLは、価格の取得に成功したときにだけ書き換わる。sid・pidを設定しても、保存済みのURLはすぐには変わらない（pipeline.py）。
- エラーログには保持期間がある（info・warning 14日、error 30日）。台帳の`errors_7d`はinfo・warningを含む合計。STEP74からerror水準の列を追加。
- 本番の`ANTHROPIC_API_KEY`は値が空（2026-10-05、Render APIで名前と空かどうかだけを確認）。本番ではClaude APIを使っていない。
- 管理APIの`fetch-rakuten`は、楽天だけでなく日次ジョブを丸ごと動かす。同じ日に2回動くと`previous_price`が上書きされ、前日比がゆがむ（監査）。
- 本番のデプロイ（push）は、日次ジョブ（6:00 JST起動）が終わってから行う。途中で再起動するとその回の実行が失われる。
- Renderの無料プランは、15分使われないとサーバーが止まる。再開に最大1分ほどかかる。（`.github/workflows/update-prices.yml`のコメント、2026-09）
- 日次ジョブ（価格取得〜レポート）は、2026-09-30時点で15分を超えるようになった。そのため、裏で実行して進み具合を確認する方式に変えた。（STEP66、Daily price update #12の失敗）
- Render無料プランには、Web Shell（コンソール）が無い。本番DBの操作は管理API経由だけ。（STEP16）
- 2026-10-05：本番DBをBasic-256mbに有料化した（承認依頼 #002）。期限は無くなった。プラン変更でDBが止まっていたのは約1分で、その間、管理APIは500を返した。Renderで有料の変更をするには、先にお支払い方法の登録が必要（APIは「Payment information is required」を返す）。
- **Renderの無料Postgresは、作成から30日で期限が切れる**。期限後はアクセスできず、14日の猶予を過ぎると全データが削除される。`golf-deals-db`の期限は2026-10-20 17:06Z。（Render API `GET /v1/postgres`、2026-10-04。https://render.com/docs/free）→ 承認依頼 #002（2026-10-05に有料化して解決。無料プランで新しいDBを作るときは、引き続き注意）
- このリポジトリには、DB全体を書き出し・取り込みするAPIが無い。CSVで取り込めるのは商品と価格だけで、IDは引き継げない。DBの引っ越しは簡単ではない。（`backend/app/csv_import.py`、SEのレビュー、2026-10-04）
- 日次ジョブのcronは6:00 JSTだが、実際の実行時刻はずれる（例：10/4は03:08Z＝12:08 JST）。本番作業と重ならないようにするには、時刻をずらすだけでなく、直前に実行中でないことを確かめる。（監査、2026-10-04）
- 本番のバックエンド・フロントエンドは、どちらもブランチ`claude/golf-deals-mvp-w7yy2l`へのpushで自動デプロイされる。（Render API `GET /v1/services`、2026-10-04）
- 2026-10-04から、作業環境のAPI認証情報で、本番の管理APIとRender APIに接続できる（値はAIからは見えない）。
- 作業環境（Claude Codeのクラウド）からは、通信先として許可したドメインにしか接続できない。（2026-10-04、reference siteで接続を拒否されて確認）

## 表示・法令
- `valuecommerce.com`はYahoo!専用ではない（ゴルフ5・アルペンなども同じドメイン）。ショップはURLから推測せず、明示して記録する（SE、2026-10-05）。
- フッターのリンクは`layout.tsx`・`SiteNav.tsx`のサイドバー・`SHEET_FOOTER_LINKS`の3か所に重なって書かれている。リンクを足すときは3か所とも直す（Webデザイン）。
- 値下がり通知は、画面を隠すだけでは止まらない（登録APIと送信処理は別）。STEP74で`PRIVACY_POLICY_PUBLISHED`を足し、3か所で止めた。
- 2026-10-05：免責ページが「Amazonは今後検討中」、FAQが「楽天のみ」「5カテゴリ」「承認するまで公開しない」と、実態と違っていた。直リンクがあるのにPR表記の無いページが9種類あった。PR表記の文字色（/35〜/45）はコントラスト2.2〜2.8:1でAAに届かなかった（STEP74で修正）。
- 個人情報を受け取るのは、値下がり通知とお問い合わせの2か所。通知には停止・削除の仕組みが無い（総務）→ #003。
- サイトマップ840件の54%（453件）が2商品比較ページで、その74%は整形されていない商品名を含む（マーケ）。
- 「最安」「必ず」などの言い切りは、景品表示法のリスクがあるため使わない。価格の取得は1日1回なので「リアルタイム」とは書かない。Amazonは価格を取得していないので「Amazon最安値」とは書かない。（STEP68）
- ~~サイトにプライバシーポリシーのページが無い（2026-10-04時点）。~~ → 2026-10-06に`/privacy`を作った（STEP75）。
- GA4は、初回のページビューでクエリを含むURL全体（page_location）を送る。URLに秘密の値（停止トークンなど）を入れるページでは、GA4を無効にする（監査、2026-10-06）。
