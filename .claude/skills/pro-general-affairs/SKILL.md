# 総務部の専門スキル

## 1. 期限の台帳（contracts.csv）
- 1行1件：サービス名／種類（ドメイン・サーバー・API・ASP・無料トライアル）／更新日・終了日／自動更新か／費用／止まったときの影響。
- 知らせる時期：**30日前**に作業ボード候補、**7日前**に急ぎ。無料枠・無料トライアルの終わりは、費用が発生する前に必ず知らせる（社長の方針）。
- 毎晩、今日から30日以内の期限を「事実」として確認する。

## 2. 法務ページの点検表
- プライバシーポリシー：何を集めるか（メールアドレス・アクセス解析・Cookie）、使う目的、第三者への提供（解析ツール・ASP）、問い合わせ先、改定日。実際の仕組みと合っているか、コードと照らす。
- 運営者情報・免責事項：価格は時点の情報であること、購入はショップとの取引であること。
- PR表記：全ページの最初の画面に1回。文字の大きさ・コントラストが本文と同等以上。Amazonアソシエイトの定型文。
- 判断に迷うものは「専門家への確認を推奨」と書く（総務は弁護士ではない）。

## 3. 社長への依頼の手順書（作業ボード）
- 冒頭に「やらないとどうなるか」と期限。手順は1動作ずつ番号を付け、押すボタンの名前とURLを書く。所要時間を書く。
- Claude in Chromeでできる部分は、そのまま貼れる依頼文を付ける。本人しかできない部分（ログイン・契約・支払い）だけを社長に残す。

## 4. 文書の整理
- docs/ の古い記述・矛盾は「どのファイルの何行目が、何と食い違うか」で書く。直す案は1つにしぼる。

## 一次情報（使う前にWebFetchで開いて確認し、確認日を knowledge.md に残す。開けなければ検索で正しいページを探す）
- 個人情報保護委員会「個人情報保護法ガイドライン（通則編）」、電気通信事業法の外部送信規律（Cookie等の送信先の公表）
- 消費者庁「ステルスマーケティング」関連ページ
- 各ASP・Amazonアソシエイトの規約が求める表示

## 育てるループ
このスキルの基準が足りなかった・外れた・古かったときは、`knowledge.md`の「スキル改善メモ」に1行で書く（`- YYYY-MM-DD [001] 何が足りなかったか → 直し案(根拠: 出典)`）。毎週土曜の代表者会議で、人事部がまとめて改訂案を出す（`docs/departments/README.md`の「スキルの育成ループ」）。

## 追加点検(2026-10-17改訂)
- 一次情報に、バリューコマース規約・Amazonアソシエイトのポリシー・消費者庁の価格表示の考え方を加える(開いて確認した日を記録)。
