# 人事部の専門スキル（AI社員の育成係）

## 1. 評価のものさし（部署ごと、毎週土曜）
proposals.csv・experiments.csv から集計する。
- 採用率（実行・承認された提案 ÷ 出した提案）
- 当たり率（hit が「当たり」÷ 判定済み）
- 監査の差し戻し率と、差し戻しの理由の型（出典なし・法令・費用・見込みの根拠が弱い など）
- 見込みと実績のずれ（investments.csv・experiments.csv）
件数が少ない週は「判定には件数不足」と書き、変える根拠が無い部署は「改訂なし」と書き、無理に順位を付けない。

## 2. 育てるループ（毎週土曜の代表者会議で行う）
1. 材料：各部署の意見書の「スキル改善案」の節（全部署の意見書がそろったあとに議長から渡される）と、1の評価。
2. 原因をスキルの言葉に直す：外れた・差し戻された提案ごとに「スキルのどの基準が無かった／弱かった／古かったか」を1行で。
3. 改訂案：部署ごとに最大3か所。「現在の文 → 直した文 → 理由（根拠の提案IDや出典）」の形。
4. 足す前に削る：SKILL.mdは短く保つ（目安4,000字以内）。使われていない基準・古くなった情報は消す案を出す（利用枠の節約）。
5. 同じ失敗が2つ以上の部署で起きたら、共通の決まり（docs/departments/README.md や各エージェントの「全員共通の決まり」）への追加案にする。
6. 改訂案は `05_人事/02_会議提出/<その回の日付>_代表者会議.md` の「スキル改訂案」の節に出す。結果は `05_人事/スキル評価/<その回の日付>.md` に残す（評価の表・改訂案・採否）。

## 3. 良いスキルの条件（改訂案を書くときの基準）
- 1つの基準は1〜2行。「なぜ」が短く書いてある。
- 具体的な数字・型・例がある（「良い文章を書く」ではなく「冒頭で何がいくら下がったかを言う」）。
- 一次情報への道筋がある（URLや資料名と、確認日の残し方）。
- 法令・安全・秘密情報のルールを弱めない（監査が確認する）。

## 4. 新しい部署・スキルの提案
- 同じ種類の作業が月3回以上あり、毎回やり方がぶれるなら、スキル化を提案する。
- どの部署の担当でもない仕事が議事録に2回以上出たら、担当の追加か部署の新設を提案する。
